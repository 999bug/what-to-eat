## 1. 项目背景与目标

### 1.1 要解决的问题
每天饭点反复纠结「吃什么」，打开外卖 App 翻十几分钟，最后随便点一家又后悔。需要一个**三秒内给出结果**的决策工具，同时能顺手留下「这个月到底吃了些什么」的记录。

### 1.2 目标
1. **决策快**：打开 → 选餐次 →（可选筛选）→ 抽 → 出结果，主路径 ≤ 3 次点击。
2. **记得住**：抽取结果一键写入当天对应餐次，形成当月三餐日历。
3. **看得懂**：月历 + 月度统计（菜系分布、三餐覆盖率、日均热量）。
4. **随处可用**：手机、平板、桌面同一套页面自适应；数据全在本地。

### 1.3 非目标（明确不做）
- 不做后端账号、云同步（v1）。
- 不做外卖下单、商家推荐、地图定位。
- **不做菜谱做法**（已确认）：v1 结果卡只给**菜名 + 所需食材**，不提供烹饪步骤；做法延后到 v1.1 以后。
- 不做精确营养计算与医学建议（热量为估算值，见 §4.7）。
- 不做社交 / 分享海报（v2 再评估）。
- 不做拍照识菜（依赖 AI 接口，超出纯前端范围）。

## 2. 竞品调研结论（详见 `竞品调研.md`）

调研了 8 类相关产品：微信小程序（吃啥呢吃、我是大吃货、随便·都可以·食、懂你的菜谱）、App（今天吃什么）、开源 Web（NiniMenu 632 道菜按菜系分类、what-to-eat / 美食大转盘 / FoodWheel 纯前端转盘）、饮食记录类（薄荷健康、MyFitnessPal、千卡记、记一餐）。

**关键结论：**

1. 市面产品分成三块且**互不打通**：随机决策类（抽完就走，记录弱）／菜谱点菜类（有菜系无热量）／饮食记录类（有热量无决策）。**「决策 → 记录」的闭环是主要空白。**
2. **菜系作为一等分类维度已被验证**（NiniMenu：川菜 73 道、湘菜 97 道、粤菜 51 道…），单菜系 30–100 道是合理量级。
3. **菜品直接带热量已被验证**（我是大吃货：拍照识菜输出「蒜蓉西兰花 95 大卡」），用户接受度高。
4. **按天/月统计视图有现成参考**（懂你的菜谱：日历 + 月合计）。
5. 纯前端 + localStorage + GitHub Pages 的技术路线在同类开源项目中完全跑得通，差距只在数据体系与记录闭环。
6. 行业经验：**单条记录录入超过 30 秒就会被放弃**——本产品必须「一键写入」，禁止让用户手填克数。

## 3. 关键决策建议：**是否先让用户选菜系？**

> 结论：**不强制，改为「默认全菜系 + 菜系作为可选筛选」的双入口设计。**

理由：
- 核心场景是「我现在很饿，快点告诉我吃什么」。强制先选菜系会把 1 次点击变成 2 次，且用户往往自己也不知道想吃什么菜系——**让他选，等于把决策难题原样还给他**。
- 但菜系确实是有效的收敛手段（今天就想吃川菜），且是记录与统计的价值维度。

因此采用如下方案：

| 模式 | 入口 | 行为 |
|---|---|---|
| **惊喜模式（默认）** | 首屏主按钮「今天吃什么」 | 全菜库按餐次 + 权重随机，结果卡片上标注所属菜系 |
| **指定模式** | 主按钮上方的菜系/口味筛选条 | 用户勾选菜系（可多选）、口味、场景后，仅在子集内抽取 |
| **记忆偏好** | 设置页 | 可设「常用菜系」为默认筛选，之后每次打开自动带上，但仍可一键清除 |

补充规则：筛选状态在**本次会话内保留**，刷新后回到默认（惊喜模式），避免用户被自己上周设的筛选困住。

| F6 | 热量估算 | P0 | 按菜品标准份热量 × 份量系数，汇总日/月，可设目标值 |
| F7 | 月度统计 | P1 | 菜系分布 TOP、三餐覆盖率、日均热量趋势、连续记录天数 |
| F8 | 收藏与黑名单 | P1 | 收藏加权、忌口过滤 |

| F11 | 自定义菜 | P1 | 用户自己录入喜欢的菜（**已实现，2026-09-20 追加**），按菜系归档，与内置菜同一套筛选管道 |

### 4.2 F1 抽签选菜（核心）

**F1.1 选择餐次**
- 首屏顶部餐次切换：早餐 / 午餐 / 晚餐 / 夜宵（**已确认：夜宵 v1 就做**，在设置中可开关，**默认关闭**；关闭时餐次切换、日历圆点、补录均不出现夜宵）。
- 自动根据当前时间推断默认餐次（06:00–10:00 早餐，10:00–15:00 午餐，15:00–21:00 晚餐，21:00 后夜宵），可手动改。
- 菜库按 `mealTypes` 字段过滤：如「豆浆油条」只在早餐出现，「牛排」不出现在早餐。

**F1.2 抽取玩法（v1 提供 2 种）**
- **转盘**：Canvas 绘制，最多展示 8 个候选格（候选 > 8 时先随机取 8 个），至少旋转 5 圈 + ease-out 减速，指针精准对齐中选格，结果卡弹出。
- **抽签桶**：候选卡片堆叠，点击后随机抽出一张，带抖动/翻牌动效。
- 玩法偏好记忆在设置里，下次默认上次的选择。
- 结果不满意可「换一个」（重新抽取，并排除刚出的结果）。

**F1.3 抽取权重与去重**
- 7 天内已吃过的菜**降权**（权重 ×0.3），不是硬排除（避免菜库被吃穿后无结果）。
- 收藏的菜**加权**（×1.5）。
- 黑名单 / 忌口命中的菜**硬排除**。
- 同一餐次重复点「换一个」时，已展示过的结果本轮不再出现。
- 以上规则在设置里可一键关闭「智能去重」。

**F1.4 结果卡片**
显示：菜名、所属菜系、图标（emoji）、热量（kcal/份）、主要食材、口味标签、难度与预计耗时、三个操作按钮：
- 「就吃这个」→ 写入当前日期 + 当前餐次（P0 主操作，一键完成）
- 「换一个」→ 重抽
- 「记入其他餐次」→ 展开选择早/中/晚后写入

**F1.5 自定义候选（v1.1）**
用户可自建「我的菜库」条目（名称 + 菜系 + 热量，热量可留空）。

> 说明：一道菜可同时属于多个分组（如「番茄炒蛋」= 家常菜；「宫保鸡丁」= 川菜 + 家常菜）。数据模型用数组标签实现，不做互斥归类。

**其他筛选维度**
- 口味：酸 / 甜 / 辣（微辣/中辣/重辣）/ 咸鲜 / 清淡
- 场景：快手（≤15 分钟）/ 下饭 / 减脂轻食 / 一人食 / 宴客硬菜
- 荤素：荤 / 素 / 荤素搭配
- 忌口（黑名单，硬过滤）：香菜、葱姜蒜、辣、花生、海鲜、牛羊肉、内脏、酒精
- 时间：≤15 分钟 / ≤30 分钟 / 不限
- 难度：简单 / 中等 / 复杂

筛选 UI：手机端为底部弹出的筛选面板（底部 Sheet），平板/桌面为右侧常驻筛选栏。已选条件以可删除的 chip 展示在首屏。

### 4.4 F3 菜库数据规格

**规模**：v1 目标 300–400 道，分布建议：八大菜系各 20–30 道，地方菜各 10–20 道，家常菜 60–80 道，外国菜 40–60 道。每餐次（早/午/晚）可用菜品 ≥ 50 道。

**字段定义**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 唯一标识，如 `dish_gongbao_jiding` |
| `name` | string | 是 | 菜名 |
| `cuisines` | string[] | 是 | 菜系标签，可多值 |
| `mealTypes` | string[] | 是 | `breakfast` / `lunch` / `dinner` / `midnight` |
| `tags` | string[] | 否 | 口味与场景标签（下饭、快手、减脂…） |
| `kcalPerServing` | number | 是 | 单人标准份热量（kcal），估算值 |
| `macros` | object | 否 | `{ protein, fat, carb }` 克/份，估算 |
| `spicyLevel` | 0–3 | 否 | 辣度 |
| `vegetarian` | boolean | 否 | 是否纯素 |
| `cookTimeMin` | number | 否 | 预计耗时 |
| `difficulty` | 1–3 | 否 | 简单/中等/复杂 |
| `icon` | string | 是 | emoji 图标（不外链图片） |
| `mainIngredients` | string[] | 否 | 主要食材 3–5 个 |
| `avoid` | string[] | 否 | 常见致敏/忌口成分（用于黑名单匹配） |

**数据示例**
```json
{
  "id": "dish_gongbao_jiding",
  "name": "宫保鸡丁",
  "cuisines": ["chuan", "home"],
  "mealTypes": ["lunch", "dinner"],
  "tags": ["下饭", "经典", "微辣"],
  "kcalPerServing": 430,
  "macros": { "protein": 28, "fat": 26, "carb": 18 },
  "spicyLevel": 1,
  "vegetarian": false,
  "cookTimeMin": 25,
  "difficulty": 2,
  "icon": "🍗",
  "mainIngredients": ["鸡腿肉", "花生米", "干辣椒"],
  "avoid": ["花生"]
}
```

**热量数据来源与口径**
- 参考《中国食物成分表（第 6 版）》及公开食物库的常见值，按**单人一份**折算。
- 数据为**估算值**，UI 必须标注「估算」；不做小数点精度，取整到 10 kcal。
- 每道菜的热量在代码里以常量形式集中维护，便于后续校准。

### 4.5 F4 三餐记录

**写入方式**
1. 抽中后点「就吃这个」→ 自动写入当天 + 当前餐次（默认份量 1 份）。
2. 月历或当日卡片中手动「补录」→ 搜索菜库选择，或自填菜名（自填时菜系可选、热量可留空）。
3. 历史记录中「再吃一次」→ 写入当前餐次。

**记录字段**
```json
{
  "id": "rec_20260920_lunch_001",
  "date": "2026-09-20",
  "meal": "lunch",
  "dishId": "dish_gongbao_jiding",
  "dishName": "宫保鸡丁",
  "cuisine": "chuan",
  "servings": 1.0,
  "kcal": 430,
  "source": "draw",
  "note": "",
  "createdAt": "2026-09-20T11:42:00+08:00"
}
```
- `source`：`draw`（抽签）/ `manual`（手动）/ `relog`（再吃一次）。
- 支持编辑（份量、备注、换菜）、删除。
- 同一餐次允许记录多道菜（一荤一素一汤），日热量为累加值。

### 4.6 F5 月历视图（P0）

**月历主视图**
- 7 列网格（周一为首列，可设置周日为首列），显示当前月份全部天数，前后补齐空白格。
- 顶部：月份切换（‹ 2026 年 9 月 ›）、「回到今天」按钮。
- **每个日期格内显示三餐状态**：三个小圆点（早/午/晚），已记录为实心主色，未记录为空心灰。鼠标悬停/长按显示菜名 tooltip。
- 当天格子高亮描边。
- 日期格右下角可显示当日总热量（设置里可关，默认在小屏关闭以免挤）。

**点击某一天 → 当天详情面板**
- 手机端：底部 Sheet 弹出；平板/桌面：右侧抽屉或居中弹窗。
- 内容按「早餐 / 午餐 / 晚餐（/ 夜宵）」分组，每组列出菜名、菜系 chip、热量、份量、备注。
- 每组有「+ 补录 / 抽一抽」入口，可直接在面板里为该餐次抽签并写入。
- 顶部显示当日合计热量 + 与目标值的进度环。
- 支持删除单条、编辑份量与备注。

**月统计条（月历下方）**
- 本月已记录天数 / 当月天数、三餐覆盖率（早/午/晚各自记录率）
- 本月菜系分布 TOP 3（带占比条）
- 本月日均热量、最高/最低一天
- 连续记录天数（streak）

### 4.7 F6 热量估算（P0）

**计算口径**
- 单条记录热量 = `菜品 kcalPerServing × 份量系数`（份量可选 0.5 / 1 / 1.5 / 2，或自定义 0.1 步进）。
- 日热量 = 当天全部餐次记录之和（自填且无热量的菜按 0 计，并标记「未知」）。
- 月热量 = 当月日热量累计；日均 = 月热量 / 已记录天数（不是除以当月天数，避免未记录的日子拉低均值）。

**目标值（可选开启，默认关闭）**
- 手动设定每日目标 kcal（默认 1800）。
- 或按 Mifflin-St Jeor 公式估算后给定：
  - BMR（男）= 10×体重kg + 6.25×身高cm − 5×年龄 + 5
  - BMR（女）= 10×体重kg + 6.25×身高cm − 5×年龄 − 161
  - TDEE = BMR × 活动系数（久坐 1.2 / 轻度 1.375 / 中度 1.55 / 高度 1.725）
- 三餐建议配比：早 30% / 午 40% / 晚 30%（仅作参考提示）。

**呈现**
- 日详情：进度环 +「已摄入 1250 / 目标 1800 kcal」，超目标时变色提示。
- 月历：可选在格内显示日热量。
- 统计页：日均热量折线/柱状趋势。

**免责声明（必须展示，设置页 + 首次进入热量模块时）**
> 热量数据为基于常见食物成分表的估算值，实际热量受食材分量、烹饪方式、油盐用量影响较大，仅供参考，不构成营养或医学建议。

### 4.8 F7 月度统计（P1）
- 菜系分布（饼图/条形）：本月各菜系被选择的次数占比。
- 三餐覆盖热力：本月早/午/晚各自的记录次数。
- 日均热量趋势：按日柱状图 + 目标线。
- 「本月之最」：最常吃的一道菜、最高热量的一天、连续记录最长天数。
- 支持切换月份查看历史。

### 4.9 F8 收藏与黑名单（P1）
- 菜品详情页可收藏 → 抽取加权 ×1.5。
- 忌口设置（黑名单）：选中项命中的菜直接排除，并在结果页提示「已为你过滤 N 道不合口味的菜」。
- 收藏与黑名单在设置页集中管理。

### 4.10 F9 数据管理（P1）
- 导出：全部记录 + 设置 + 自定义菜库 → JSON 文件下载。
- 导入：读取 JSON 覆盖或合并（提示用户确认）；自定义菜按「菜名 + 热量」去重合并，**本地已有的同名菜优先保留**。
- 清空：二次确认后清空记录（保留菜库）。
- 首次进入时提示「数据仅保存在本设备浏览器中，清理浏览器数据会丢失，建议定期导出备份」。

### 4.11 F11 自定义菜（P1，2026-09-20 追加）

**背景**：每个人的口味不一样，内置菜库再大也可能没有「妈妈做的红烧肉」。让用户把自己的菜加进去。

**F11.1 录入原则：快**
- **菜名是唯一必填项**。只填菜名 + 回车即可保存，其余全部有合理默认值。
- 热量可选：输入框旁边直接标「不知道就留空」；留空按**热量未知**处理（详见 F11.4）。
- 菜系、餐次、口味、难度、所需食材收在「更多选项」里，默认折叠，不干扰快速录入。
- 图标从 12 个常用 emoji 里点选，默认 `🍽️`。

**F11.2 三个入口**
- 设置页 →「我的菜」→ 顶部「＋ 添加」。
- 抽取页搜索框旁「＋ 新菜」。
- 抽取页搜索无结果时 →「＋ 手动添加「搜索词」」（菜名自动带入，省一次输入）。
- **抽取页录入后立即记入当前餐次**，不需要「先保存再回去重选」。

**F11.3 管理与菜系**
- 「我的菜」列表按录入时间倒序，每行显示图标、菜名、菜系/餐次/难度摘要、热量（或「热量未知」）。
- 可随时编辑或删除；**编辑保留 id**，因此已经吃过的历史记录不会与新名字失联。
- 删除时同步清掉收藏与「已展示」里的引用，避免脏 id 影响去重。
- 按菜系归档：默认「家常」，可选内置全部菜系（川/粤/鲁/苏/浙/闽/湘/徽 + 地方 + 外国 + 家常）。
- **自定义菜与内置菜走完全相同的筛选管道**（餐次 / 菜系 / 口味 / 难度 / 忌口），不存在绕过忌口的可能。

**F11.4 未知热量的统计口径（重要）**
- 自定义菜没填热量 → 记录 `kcalKnown = false`、`kcal = 0`，界面一律显示「热量未知」而不是「0 kcal」。
- 日均的**分母只统计「至少有一条已知热量记录」的天数**，不把未知当 0 稀释均值。
  - 例：某天 600 kcal，另一天只有未知记录 → 日均 = 600（不是 300）。
  - 全部都是未知 → 日均 = 0（不出现 NaN）。
- 统计页与日历页显式提示「另有 N 条记录（M 天）未填热量，已排除在日均之外」；日面板显示当日未填条数。
- 老数据没有 `kcalKnown` 字段 → 一律视为**已知**，历史统计结果保持不变。

## 7. 技术方案

### 7.1 选型建议

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **A. Vite + React 18 + TypeScript**（推荐） | 组件化好维护；月历/统计逻辑复杂，React 更顺手；TS 保障数据结构；可直接 GitHub Pages 部署；与既有项目技术栈一致 | 需要构建步骤 | ✅ 推荐 |
| B. 单文件 HTML + 原生 JS | 双击即开，零依赖 | 月历 + 统计 + 筛选状态管理会迅速变成面条代码，300+ 菜库数据维护困难 | ❌ 不推荐（后续扩展成本高） |
| C. Vue 3 + Vite | 同样可行 | 与既有项目栈不一致 | 可选 |

**配套**
- 状态管理：`zustand`（轻量，与既有项目一致）
- 存储：`localStorage`（记录量小，单条 ≈ 200B，一年 ≈ 220KB，可控）；若后续加入自定义菜库与照片再迁移 IndexedDB（Dexie）
- 图表：自绘 SVG / 极简条形（不引入图表库，控制体积）
- 部署：GitHub Pages（CI 构建 dist）
- 无框架 UI 库，手写 CSS（CSS Modules 或单文件 CSS 变量体系）

### 7.2 存储键设计（localStorage，全部加 `wte:v1:` 前缀）

| Key | 内容 |
|---|---|
| `wte:v1:records` | 记录数组 `Record[]` |
| `wte:v1:settings` | 主题、默认餐次、玩法偏好、忌口、热量目标、是否开启夜宵 |
| `wte:v1:favorites` | 收藏菜品 id 数组 |
| `wte:v1:customDishes` | 自定义菜品 `CustomDish[]`（v1.0.2 已实现） |
| `wte:v1:onboarded` | 是否已完成首次引导 |

写入策略：每次变更立即落盘；解析失败时降级为空数据并提示，不阻塞页面。

> 实现备注：`customDishes` **不放进 `settings`**，而是 store 顶层独立字段 + 独立键。
> settings 属于「配置」（导入时覆盖），自定义菜属于「用户数据」（导入时合并、有增删改生命周期），混在一起会让合并逻辑变脏。

## 9. 验收标准（v1.0）

1. **响应式**：375px（iPhone SE）、768px（iPad 竖）、1440px（桌面）三档下均无横向滚动、无内容溢出、按钮可点区域达标。
2. **抽取正确性**：选择早餐时不会抽到仅适用于午/晚餐的菜；勾选「川菜」后结果 100% 属于川菜；忌口命中菜不出现。
3. **去重**：开启智能去重时，连续抽 10 次不出现 7 天内已吃过的菜（若菜库耗尽则降级并提示）。
4. **记录闭环**：抽中点「就吃这个」后，切到日历 → 点击今天 → 对应餐次下能看到该菜，刷新页面后仍存在。
5. **月历正确性**：正确显示当月天数（含 2 月与闰年）、周一/周日首列设置生效、前后补齐空白格、点击任意日期弹出对应详情。
6. **热量**：份量 1.5 倍时热量为基准值 ×1.5；日合计 = 当天各条之和；未开启目标值时不显示进度环。
7. **数据持久化**：清除浏览器数据前有导出备份提示；导入 JSON 后记录完整还原。
8. **性能**：首屏 ≤ 1.5s，转盘动画无掉帧，菜库加载不阻塞交互。
9. **视觉**：亮/暗两模式均通过对比度检查，无外链资源请求（Network 面板验证）。
