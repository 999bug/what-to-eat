# what-to-eat · 今天吃什么

解决「今天吃什么」的纯前端随机选菜工具：抽签决定菜品 → 一键记入三餐 → 月历回看 → 热量估算。
手机 / 平板 / 桌面响应式，无后端、无账号，数据全部保存在本地浏览器。

**线上地址**：<https://999bug.github.io/what-to-eat/>

## 它能做什么

- **抽签**：按当前时间自动选中早/午/晚（夜宵可在设置开启），转盘或抽签桶两种玩法；菜系、口味场景、做菜难度、忌口都是**可选筛选**，默认全菜库「惊喜模式」。
- **结果**：抽出后居中弹出结果卡，给菜名、所需食材、热量估算与做菜难度；可「就吃这个」一键记入当天，也可以换一个（会重新转一次转盘）、收藏、记入其他餐次。
- **记录与日历**：月历按天显示三餐圆点与热量，点任意一天看三餐明细，支持补录与就地抽取。
- **统计**：本月菜系分布、三餐覆盖、每日热量趋势与日均、本月吃得最多。
- **设置**：深浅/跟随系统主题、夜宵开关、智能去重、默认份量、忌口、每日热量目标、数据导出/导入与重置。

v1 只给**菜名 + 所需食材**，不出菜谱做法。

## 原型与正式版

- `prototype/` 是**评审用原型**（免构建，双击 `app.html` 即可打开），已冻结，不再随正式版演进。
- `src/` 是**正式版**：Vite + React 19 + TypeScript + zustand，配色暖米白 `#F5F1EA` + 番茄红 `#D6453D`。

## 技术栈与分层

```
data（菜库/元数据/种子） → lib（日期/抽取/统计/存储/版本 纯函数） → stores（zustand） → components/pages
```

- 抽取口径集中在 `src/lib/pool.ts`（7 天内吃过 ×0.3、收藏 ×1.5、忌口硬过滤、转盘候选 8 个）。
- 统计口径集中在 `src/lib/stats.ts`（日均 = 当月总热量 ÷ **已记录天数**，不按当月天数）。
- 组件只调 store actions，不直接碰 localStorage。
- 数据存 localStorage（键前缀 `wte:v1:`），支持导出/导入备份；热量为估算值，取整到 10 kcal/份。

## 版本与更新提示

- 版本号来自 `package.json`，构建时注入 `__APP_VERSION__`；更新日志在 `src/changelog/changelogData.ts`（有测试断言两者同步）。
- 构建会在产物根目录产出 `version.json`。前端在进入页面、每小时、切回标签页/窗口聚焦时各检测一次：
  线上版本比本地新时，首页出现「有新版本 · 点此刷新」，点击刷新即可（纯静态站点，无 Service Worker，刷新是取新版的唯一方式）。
- 首页顶部「版本说明」入口可查看当前版本、完整更新日志，并手动检查更新。

## 核心结论速览

- **关键决策**：菜系**不强制**前置选择，避免把「吃什么」这个难题原样还给用户。
- **差异化**：市面「随机决策类」与「饮食记录类」互不打通，本产品补的是「抽 → 记 → 看」这条闭环。
- **隐私**：无后端、无账号、不上传；清理浏览器数据会丢失记录，建议定期导出备份。
